# change_1007 本地验证

使用本地可获得的 16 个实例真实 base commit，另从服务器只读导出 Conan-16871 的
base tree，共 17 个样例。所有源码都来自 `git archive <base_commit>`，没有使用当前
工作区中可能已包含模型修改的文件。16 个本地快照保留只读 Git 历史访问；
Conan-16871 是不含历史的源码 archive，因此该例的 v5 模式无法使用历史检索。

原仓库基线是 `b67f93b`。`v5` 模式使用迁入后的历史检索和完整 AST 解析；
`expanded` 在此基础上加入调用、状态和导出路径扩展。

`recall_17.json` 比较三个模式。修复文件指参考补丁修改的生产 Python 文件；
“额外修复文件”指没有出现在 `new_components` 中的修复文件。统计是否进入最终
prompt 的 `<code>`，不只是候选列表。生成输出格式示例里的文件名不计入统计。

|模式|修复文件召回|额外修复文件召回|
|---|---:|---:|
|原始 main (`b67f93b`)|19/27（70.4%）|1/9（11.1%）|
|迁入后的 v5 模式|20/27（74.1%）|2/9（22.2%）|
|增强检索|27/27（100%）|9/9（100%）|

在该轮测试中，平均进入 code 部分的文件数分别约为 1.7、2.8、11.4。增强检索提供
了更多上下文，候选文件不代表全部都需要编辑。新加入的状态写入分支提示另在
`recall_17_state_flow.json` 中验证，保留具体函数/行号和生产者、消费者证据。

补回的额外位置包括：

- Conan-16871：`conans/client/graph/compute_pid.py`。
- Conan-10154：新 symlinks 包的 initializer 和 `conan/tools/files/__init__.py`。
- Roboflow-245、Roboflow-910：声明目标外的检测辅助代码。
- SQLGlot-1252、Boto3-74：目标模块之外的相关生产代码。

Conan-16871 的新证据定位到 `compute_package_id` 和 `run_validate_package_id`，并追踪
`cant_build` 等字段的写入与 GraphBinariesAnalyzer 的消费关系。原始服务器 v5 产物
其实也包含过 `compute_pid.py`，但其编辑将 `cant_build` 和 `invalid` 同时设置为同一个
异常；因此“包含文件”不能视为正确修复。这次增强的重点还包括职责和分支位置。

这 17 个样例是缓存可用的小样本，并非随机划分或完整 200 例。包导出检索是在看到
小样本的召回遗漏后改进的，所以这些成绩属于开发集结果，需要其他实例验证泛化。
参考补丁只用于事后评分。没有调用模型进行新一轮求解，也没有重跑 SWE-bench；
这里的 100% 是文件召回率，不是解决率。检索依赖静态 Python 关系，动态注册和反射
仍可能遗漏；状态字段同名也可能带来额外候选。
